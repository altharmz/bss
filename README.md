# bss

A **billing and subscriber management system** for a telecom-style subscription
business, built on the **TM Forum SID** data model and the **TMF Open APIs**. It is
demo-sized but rule-complete: every money rule is enforced in code and proven by tests.

- **Backend**: FastAPI + PostgreSQL 16 (psycopg 3, hand-written Alembic migrations).
  Money is `Decimal`; the only wall-clock reader is `app/clock.py`.
- **Billing worker**: a separate process (same image) that runs the daily billing run:
  pro-rata recurring charges and refunds, bills on each account's cycle day, settlement,
  catch-up and retry.
- **Admin console**: React + TypeScript (Vite) for operators: subscribers, catalog,
  billing runs, financial accounts.
- **MCP connector** (`bss_mcp/`): the API as tools for Claude, ChatGPT, Cursor, with
  OAuth 2.1 or static tokens and `read`/`write` scopes ([docs/mcp.md](docs/mcp.md)).

## What is built

| Area | Contents |
|---|---|
| TMF620 Product Catalog | specifications, offerings, prices (monthly recurring), categories, catalogs; deleting entries nothing references; import/export jobs |
| TMF622 Product Ordering | orders that add and end products, synchronous processing |
| TMF629 / TMF632 | customers; individuals and organizations |
| TMF637 Product Inventory | products (read-only; only orders create or end them) |
| TMF666 Account | billing accounts with balance and credit limit; financial, party and settlement accounts; bill formats and presentation media; billing cycle specification |
| TMF676 Payment (v4) | payments allocated to bills; refunds paid out of unused credit |
| TMF678 Customer Bill | bills, applied billing rates, bill cycles, on-demand bills |
| TMF635 / TMF639 | usage records from the network feed; SIM, eSIM and IMSI resources |
| TMF654 / TMF670 (v4) | prepaid balances, top-ups and adjustments; saved cards |
| TMF681 (v4) | customer SMS and email message log |
| Internal API (`/internal/v1`) | what the admin UI needs beyond TMF: charges, transactions, settlement, billing runs, porting, prepaid lifecycle settings, account security |
| Prepaid MVNO (epic #182) | prepaid plans and pay-as-you-go on a direct T-Mobile connection; network, tax, payment and messaging behind placeholder adapters ([decision](docs/decisions/prepaid.md#prepaid-mvno-on-t-mobile-scope-and-integration-pattern-2026-11-05-epic-182)) |

The vendored specs in `spec/` are the contract: every response in the test suite is
validated against them. Coverage of the specs' non-listener operations is **129 of 129**
(2026-10-17, event hubs included); the deviations from the specs are recorded by
decision - see
[docs/tmf-gap-analysis.md](docs/tmf-gap-analysis.md). Implementation and test status
per item: [docs/PROGRESS.md](docs/PROGRESS.md), generated by `make progress`.

Out of scope: real connections to T-Mobile, a tax engine, a payment gateway and an
SMS/email provider (placeholders today); vouchers and PIN cards; self-care; real-time
online charging; extending postpaid (dunning, external bill delivery)
([docs/overview.md](docs/overview.md#scope)).

## Quick start (WSL2)

Everything runs in containers; Node never runs on the host. Keep the repository in the
Linux filesystem (not under `/mnt/c`), or hot reload breaks.

```bash
make up            # app + local postgres, hot reload on http://localhost:8081 (APP_PORT)
make migrate       # schema to head
make seed          # demo data through the public TMF API (local only; re-run is a no-op)
make web-install   # once: npm ci into the node_modules volume
make web-dev       # admin UI on http://localhost:5173
```

`.env` comes from `.env.example`. Never read or commit `.env*`.

## Checks and deploy

```bash
make lint && make test   # ruff; the full suite (pytest, one throwaway database per test); the commit hook runs the smoke and affected tests only
make check               # on demand: lint, test (ci), docs-check, web-lint, web-test, web-e2e
make verify              # = make deploy: ship to the VPS and smoke-test it there
```

VPS is a small server whose main job is a VPN server. bss runs next to it under
strict limits, and PostgreSQL, Caddy and backups belong to the separate **vps-infra**
project. Images are built locally and shipped (`make deploy`, `scripts/deploy.sh`);
**never build on the VPS**. Details: [docs/operations.md](docs/operations.md);
rules: [CLAUDE.md](CLAUDE.md#rules).
